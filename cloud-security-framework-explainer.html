ประกาศสำนักงาน สกมช. เวอร์ชัน 1.0 10 มีนาคม 2568 ฉบับอ่านง่าย · ไม่ใช่เอกสารทางกฎหมาย

กรอบการทำงานด้านการรักษาความมั่นคงปลอดภัยไซเบอร์ระบบคลาวด์

Thailand's National Cloud Security Framework — คู่มือ/เครื่องมือช่วยให้หน่วยงานเตรียมความพร้อมนำมาตรฐานฯ 2567 ไปปฏิบัติได้จริง พร้อมบทเรียนจาก 4 ประเทศและแผนขับเคลื่อน 5 ขั้นตอน

ประกาศ ณ วันที่ 10 มี.ค. 2568 ผู้ลงนาม พลอากาศตรี อมร ชมเชย เลขาธิการ กมช. ฐานอำนาจ ข้อ 7 ของประกาศมาตรฐานฯ 2567
ความสัมพันธ์กับมาตรฐานฯ 2567: เอกสารนี้ไม่ใช่ข้อบังคับใหม่ แต่เป็น "แนวทาง" ที่เลขาธิการ กมช. ออกเพื่อช่วยให้การปฏิบัติตามประกาศ กมช. เรื่อง มาตรฐานด้านการรักษาความมั่นคงปลอดภัยไซเบอร์ระบบคลาวด์ พ.ศ. 2567 มีประสิทธิภาพมากขึ้น
เอกสารนี้ (กรอบการทำงาน)
มีผลบังคับใช้แล้ว ตั้งแต่วันประกาศ 10 มี.ค. 2568
มาตรฐานฯ 2567 (ข้อบังคับหลัก)
มีผลบังคับใช้ 10 ก.ย. 2569 (พ้น 2 ปีหลังประกาศ)

  3. ข้อค้นพบและข้อเสนอแนะเชิงนโยบาย

  8. เอกสารอ้างอิง

ที่มาและวัตถุประสงค์การศึกษา

ประเทศไทยกำหนดนโยบาย Cloud First Policy ภายใต้แผนพัฒนาดิจิทัลแห่งชาติ ตั้งเป้าให้ไทยเป็นศูนย์กลางเศรษฐกิจดิจิทัลในภูมิภาค โดยตั้งเป้าย้ายระบบหน่วยงานรัฐกว่า 10% ขึ้นคลาวด์ภายในปี 2025 แต่ ThaiCERT รายงานว่าการโจมตีไซเบอร์ปี 2023 เพิ่มขึ้นอย่างมีนัยสำคัญ โดยเฉพาะภาคการศึกษาและหน่วยงานรัฐ จึงต้องศึกษาแนวทางจากต่างประเทศเพื่อออกแบบกรอบงานของไทยให้เหมาะสม

10%
เป้าหมายย้ายระบบหน่วยงานรัฐขึ้นคลาวด์ภายในปี 2025
4 ประเทศ
ศึกษาเทียบเคียง: สิงคโปร์ สหรัฐฯ ออสเตรเลีย อินเดีย
3 ระยะ
แผนดำเนินการศึกษา: วางแผน → ศึกษา/ร่างนโยบาย → สรุปผล
วัตถุประสงค์การศึกษา 3 ข้อ: (1) ศึกษาวิเคราะห์เปรียบเทียบนโยบายและ Framework จากนานาประเทศ (2) ศึกษาวิเคราะห์เปรียบเทียบแนวทางและมาตรฐานด้าน Cloud Security (3) สนับสนุนการร่างกฎระเบียบและมาตรฐานด้าน Cloud Security ของไทย

เทียบ 4 ประเทศ: ใครทำอย่างไรบ้าง

แตะปุ่มประเทศเพื่อดูรายละเอียด — สรุปจากงานวิจัยเปรียบเทียบในเอกสาร (ข้อมูล ณ ช่วงต้นถึงกลางปี 2567 สถานะกฎหมายของแต่ละประเทศอาจเปลี่ยนแปลงไปแล้วนับแต่วันที่จัดทำรายงาน)

ข้อค้นพบและข้อเสนอแนะเชิงนโยบาย

สรุปสิ่งที่พบจากต่างประเทศ เทียบกับข้อเสนอแนะที่ สกมช. นำมาปรับใช้กับบริบทไทยใน 5 ด้าน

วัตถุประสงค์ ประโยชน์ และหลักการของกรอบงาน

วัตถุประสงค์ 3 ข้อ

(1) ผลักดันมาตรฐานฯ 2567 ให้เกิดผลรวดเร็ว สะดวก มีประสิทธิภาพ (2) ยกระดับความมั่นคงปลอดภัยทั้งฝั่ง CSC และ CSP (3) บูรณาการการทำงานระหว่าง สกมช. กับหน่วยงานที่เกี่ยวข้อง

ประโยชน์ 3 ข้อ

(1) ลดความซ้ำซ้อน ความไม่สอดคล้อง และต้นทุนที่ไม่จำเป็น (2) สร้างความร่วมมือรัฐ-เอกชนเพื่อส่งเสริมนวัตกรรมคลาวด์ที่ปลอดภัย (3) ช่วยหน่วยงานรัฐเร่งใช้คลาวด์อย่างโปร่งใสและมีการบริหารความเสี่ยง

หลักการสำคัญที่เกี่ยวข้อง (เอกสารฐาน 6 ฉบับ)

1. มาตรฐานฯ 2567

ประกาศ กมช. เรื่อง มาตรฐานด้านการรักษาความมั่นคงปลอดภัยไซเบอร์ระบบคลาวด์ — ข้อบังคับหลักที่กรอบงานนี้ช่วยขับเคลื่อน

2. มาตรฐานคุณลักษณะฯ 2566

ใช้จัดระดับผลกระทบต่ำ/กลาง/สูงของข้อมูลหรือระบบสารสนเทศ

3. มาตรฐานผู้ให้บริการตรวจรับรอง 2566

แนวทางส่งเสริมพัฒนาระบบการให้บริการตรวจรับรองด้านความมั่นคงปลอดภัยไซเบอร์

4. หลักเกณฑ์หน่วยงาน CII 2564

กำหนดลักษณะหน่วยงานที่เป็น CII และการมอบหมายควบคุม/กำกับดูแล

5. ประกาศ กกม. หน้าที่หน่วยงาน 2567

หน้าที่ของหน่วยงาน CII และหน่วยงานควบคุม/กำกับดูแล

6. แนวทางแผนความมั่นคงปลอดภัยไซเบอร์ 2567

ประกาศ สกมช. เรื่องแนวทางการจัดทำแผนการรักษาความมั่นคงปลอดภัยไซเบอร์

ผู้ที่เกี่ยวข้อง — 10 บทบาท

คลิกแต่ละบทบาทเพื่อดูหน้าที่โดยย่อ

จุดที่มักสับสน: "หน่วยงานให้บริการตรวจรับรอง (Certify Body)" คือองค์กรที่ออกใบรับรอง ส่วน "ผู้ตรวจสอบด้านความมั่นคงปลอดภัยไซเบอร์ระบบคลาวด์ (Cloud Security Auditor)" คือตัวบุคคลที่ลงมือตรวจจริง และ "ผู้ปฏิบัติงานด้านความมั่นคงปลอดภัยไซเบอร์ระบบคลาวด์ (Cloud Security Professional)" คือผู้เชี่ยวชาญที่ดูแลปกป้องระบบในงานประจำวัน ไม่ใช่ผู้ตรวจสอบ — สามบทบาทนี้แยกจากกันชัดเจน

แผนขับเคลื่อน 5 ขั้นตอน

กรอบแนวทางที่ สกมช. ใช้ผลักดันการเตรียมพร้อมร่วมกับหน่วยงานต่าง ๆ ก่อนมาตรฐานฯ 2567 มีผลบังคับใช้จริงในปี 2569 — คลิกแต่ละขั้นเพื่อดูรายละเอียดและตัวอย่าง

ข้อกำหนดทั่วไปในตัวประกาศ

ข้อ 1 — ชื่อประกาศ

"ประกาศสำนักงานคณะกรรมการการรักษาความมั่นคงปลอดภัยไซเบอร์แห่งชาติ เรื่อง กรอบการทำงานด้านการรักษาความมั่นคงปลอดภัยไซเบอร์ระบบคลาวด์ (Thailand's National Cloud Security Framework)"

ข้อ 2 — วันบังคับใช้

ให้ใช้บังคับตั้งแต่วันประกาศเป็นต้นไป (มีผลทันที ต่างจากมาตรฐานฯ 2567 ที่ต้องรอ 2 ปี)

ข้อ 3 — วิธีปฏิบัติ

ให้หน่วยงานของรัฐ หน่วยงานควบคุม/กำกับดูแล หน่วยงาน CII และหน่วยงานอื่นที่เกี่ยวข้อง นำกรอบการทำงานแนบท้ายมาใช้เป็น "แนวทาง" ในการดำเนินการของตน

การตีความ

หากมีปัญหาการปฏิบัติตามประกาศ หรือประกาศไม่ได้กำหนดไว้ ให้เลขาธิการมีอำนาจตีความและวินิจฉัยชี้ขาด แล้วรายงานให้ กมช. ทราบ คำวินิจฉัยของเลขาธิการถือเป็นที่สุด

เอกสารอ้างอิงและแหล่งที่มา

  • กรอบการทำงานด้านการรักษาความมั่นคงปลอดภัยไซเบอร์ระบบคลาวด์ (Thailand's National Cloud Security Framework) เวอร์ชัน 1.0 — สกมช., จัดทำร่วมกับ ดร. ธัชพล โปษยานนท์ และบริษัท พาโล อัลโต เน็ตเวิร์กส์ (ประเทศไทย) จำกัด
  • ประกาศ กมช. เรื่อง มาตรฐานด้านการรักษาความมั่นคงปลอดภัยไซเบอร์ระบบคลาวด์ พ.ศ. 2567 — ข้อบังคับหลักที่กรอบงานนี้ใช้สนับสนุน
  • MTCS SS (Multi-Tier Cloud Security Standard) — สิงคโปร์, จัดทำโดย IMDA/CSA
  • NIST SP 800-53 / NIST SP 800-144 / FedRAMP — สหรัฐอเมริกา
  • ISM (Information Security Manual) — ออสเตรเลีย, จัดทำโดย ASD
  • Cloud Security Guidelines / Baseline — อินเดีย, จัดทำโดย MeitY
หมายเหตุ — หน้านี้เป็นบทสรุปภาษาที่เข้าใจง่ายเพื่อการศึกษา จัดทำจากประกาศสำนักงานคณะกรรมการการรักษาความมั่นคงปลอดภัยไซเบอร์แห่งชาติ เรื่อง กรอบการทำงานด้านการรักษาความมั่นคงปลอดภัยไซเบอร์ระบบคลาวด์ เวอร์ชัน 1.0 (ประกาศ ณ 10 มีนาคม 2568) เนื้อหาส่วนเปรียบเทียบต่างประเทศเป็นการสรุปประเด็นสำคัญ ไม่ใช่การแปลทุกถ้อยคำ ไม่ใช่เอกสารทางกฎหมายที่ใช้อ้างอิงอย่างเป็นทางการ กรุณาตรวจสอบต้นฉบับก่อนนำไปใช้ปฏิบัติงานจริง
